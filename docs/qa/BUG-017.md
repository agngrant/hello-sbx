# BUG-017 — Boss feature has no `tests/test_boss.py`; backend boss behavior is entirely untested

**Severity:** P2 (feature-shipping test-coverage gap: the QA gate for
`feat/boss-entity` explicitly requires the pytest suite to include
`tests/test_boss.py`, but the file does not exist — so every boss
behavior in `app/boss.py` is verified only by manual reasoning, and the
gate cannot be satisfied as written.)

**Component:** Tests — `tests/` (missing `tests/test_boss.py`); exercises
`app/boss.py` (`Boss`, `roll_damage`, `Boss.turn`).

## Observed
- `find . -name "test_*boss*"` → no matches; `tests/` contains no boss
  tests at all (confirmed 2025-09-15 on `feat/boss-entity` @ `bf5f4dc`).
- Full suite run (`python -m pytest tests/ -q`): 0 tests collected for the
  boss module; the gate's required command
  `pytest -q tests/test_boss.py` collects nothing.
- Every boss AC from `docs/specs/boss-entity.md` (roll range, turn-order
  integration, spawn/end rules) is therefore uncodified in the test
  suite.

## Impact
- The QA sign-off for this feature has no regression net; a future
  regression in damage rolls or boss turn behavior would not be caught.
- QA gate step 1 ("run the backend test suite including
  tests/test_boss.py") cannot pass.

## Suggested fix
Add `tests/test_boss.py` covering at minimum: `roll_damage` range
invariants (min/max over N rolls, seeded RNG), `Boss.turn` action
semantics, and the session/battle integration points named in the spec.

**QA:** agent-QA (this feature's QA gate), `feat/boss-entity` @ `bf5f4dc`.
