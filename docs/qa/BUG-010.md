# BUG-010 — "New entity" offers kind `player`, which the server always rejects

**Severity:** P3 (minor — dead UI option)
**Component:** Frontend `app/static/index.html` ↔ backend `app/session.py`

## File:line
- `app/static/index.html:160` — `<option value="player">player</option>` in `#new-entity-kind`
- `app/session.py:57` — `CREATABLE_KINDS = ("npc", "enemy", "gm_character")`
- `app/session.py:514-516` — `if kind not in CREATABLE_KINDS: return {… "kind must be one of npc/enemy/gm_character"}`

## Repro steps
1. GM selects **New entity**, kind = `player`, name anything, click **Add**.
2. Toast: `kind must be one of npc/enemy/gm_character`.

## Expected vs actual
- **Expected:** every offered option succeeds (or the option is not offered).
- **Actual:** `player` is offered (wireframes §6 lists `player|npc|enemy|gm_character`) but the server rejects it because player characters are only created on `join`.

## Proposed fix
Remove the `player` option from `#new-entity-kind` (keeps UI honest), or (if "GM creates a spare player token" is wanted) add `"player"` to `CREATABLE_KINDS` with `owner=None`.
