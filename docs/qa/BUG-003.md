# BUG-003 — Path animation mutates a detached object; `state.animating` never gates input

**Severity:** P2 (moderate — soft requirement "smooth animated movement" is effectively a teleport)
**Component:** Frontend — `app/static/app.js`

## File:line
- `app/static/app.js:209` — `onPath(msg)`
- `app/static/app.js:219` — `if (ent.x === last.x && ent.y === last.y) return;` (the "skip if already reconciled" guard)
- `app/static/app.js:221` — `state.animating.add(msg.entity_id)` (added, later deleted, **never read**)
- `app/static/app.js:229-230` — `ent.x = pts[i].x; ent.y = pts[i].y;` (mutates the captured `ent`)
- `app/session.py:464` — `self._broadcast(extra=frame)` sends the `path` frame **before** the `state` snapshot

## Why it's wrong
The in-code comment claims "the sender receives the state snapshot (final position) **before** its own path reply". The server does the opposite: `_broadcast(extra=frame)` sends `extra` (the `path` frame) first, then the per-viewer `state` snapshot. So the client processes:

1. `path` → `onPath` runs while `ent` is still at the **start** cell, so the guard on line 219 does not fire; it schedules a 120 ms/cell animation that mutates `ent` (a reference into the *current* `state.entities`/`state.youEntity`).
2. `state` (same batch) → `applyState` **replaces** `state.entities` (new array of new entity objects at the final position) and `state.youEntity`, then `renderAll()` draws the token at the final position.

Net effect: the token **snaps** to the destination immediately, and the `setTimeout` animation keeps mutating a now-detached object that is no longer in `state`, so the "120 ms/cell" motion is never visible. This holds for both GM (new `state.entities` array) and players (new `state.youEntity` object).

Additionally, `state.animating` is written (lines 100/221/226) but **never read**, so the wireframes §4.5 rule "while animating, ignore further move clicks for that entity" is not implemented.

## Repro steps
1. (Requires BUG-001 fixed.) GM or player selects their character, clicks a destination 3+ cells away on open floor.
2. Observe the token jump straight to the destination instead of moving cell-by-cell.

## Expected vs actual
- **Expected:** token animates along `path` at 120 ms/cell; extra clicks on that entity are ignored mid-animation.
- **Actual:** token teleports to the destination; `state.animating` is dead; extra clicks are not gated.

## Proposed fix
Make the animation authoritative over the live reference, not a detached one. Simplest correct approach: drive the animation from the *current* state each tick — store `{entity_id, path, i}` and, on each tick, look the entity up in `allEntities()` and update *that* object; and/or have `applyState` skip re-rendering/overwriting an entity that is currently animating (or, cleaner, don't send the position-changing `state` until the animation is done, or have the client treat `state` positions as authoritative only when not animating). Also actually consult `state.animating` in the click/keyboard move handlers to drop clicks for an in-flight entity.
