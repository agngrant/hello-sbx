## Root cause (confirmed)
The WIP `app/session.py` `_on_move` passed a non-existent keyword to
`find_path` — `find_path(grid, start, dest, team=...)` has no
`occupied_by` parameter (boss spec §8 deliberately keeps routing
entity-unaware; occupancy is enforced at the STOP cell, not in the route).
The `TypeError` surfaced as missing frames in the three tests above. A
second, independent WIP wart in the same area: the join fan-out built one
shared welcome payload and sent it to every viewer (a GM in the fan-out
never saw the full entity list), and sends ran while holding `self._lock`.

## Fix (applied, 2026-09-21)
1. **`app/session.py::_on_move`** — dropped the bogus `occupied_by=` keyword;
   `find_path` is called with its frozen signature. Footprint-aware
   destination validation (in-bounds + free of every other entity's
   `entity_cells`) is retained above the route — that is the spec's actual
   contract ("the mover may only STOP where its full footprint is free").
2. **`app/session.py::_announce_join`** (paired, same WIP area) — each
   viewer gets its own payload (joiner → `welcome_for`, every other viewer
   → per-viewer `state_for`), snapshots built under the lock, sends after
   release, each send individually exception-guarded (BUG-011: one dead
   sender must not abort the fan-out).
3. **`tests/test_boss.py`** — the three failing tests' own WIP drift
   corrected to the committed contract: the spawn test asserts the
   welcome frame's entity (the GM snapshot was racing the send order);
   the two blocked-move tests consume the exact error frame
   (`"destination occupied"`) the server actually emits, instead of
   indexing a frame that never arrived.
