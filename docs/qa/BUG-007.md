# BUG-007 — `entityAtCell()` never finds a player's own token; "re-assert selection" branch is dead

**Severity:** P2 (moderate — wireframe §4.5 behavior not implemented; clicking your own token moves you)
**Component:** Frontend — `app/static/app.js`

## File:line
- `app/static/app.js:700-706` — `entityAtCell(x, y)`
- `app/static/app.js:789-790` — click handler: `if (!gm && hit && hit.id === state.you.entity_id) { selectEntity(hit.id); return; }`

## Why it's wrong
`entityAtCell` builds its search list as:

```js
const all = state.role === "gm" ? state.entities
  : [...state.entities,
     ...(state.you ? [state.entities.find((e) => e.id === state.you.entity_id)].filter(Boolean) : [])];
```

For a **player**, `state.entities` is `[]` (the server sends players an empty `entities` list — their character arrives only in `you_entity`/`state.youEntity`). The second array spreads `state.entities.find(e => e.id === state.you.entity_id)` — but `state.entities` is empty, so `.find()` returns `undefined`, `.filter(Boolean)` drops it, and `all` is `[]`. So `entityAtCell` returns `null` for **every** cell in a player's view, including the cell under their own token.

Therefore the "Player clicking their own token: re-assert selection (no move)" branch at line 789 **never fires** for a player: `hit` is always `null`, so clicking one's own token falls through to the movement logic (line 804-806) and **moves the character** to that cell (a no-op move to its own cell) instead of simply re-asserting selection. The intended UX — a deliberate first tap on your own token that selects (and does not move) it — is not achievable by clicking the token; only by the arrow-key path or a two-tap where the first tap is elsewhere.

**Impact:** clicking your own character unexpectedly issues a move request rather than a selection; the "first tap selects" two-tap model documented in wireframes §4.5 is not realizable for a player's own token. (Movement still works, hence P2, not P0/P1.)

## Repro steps
1. (Requires BUG-001 fixed.) Join as a player; your token is pre-selected.
2. Click directly on your own token.
3. A `move` to your own current cell is sent (visible in the WS / a `path` confirm frame) rather than a silent re-selection. There is no way to "tap my token to select it" without also moving.

## Expected vs actual
- **Expected (wireframes §4.5):** "Player → own character → selects (re-asserts selection)".
- **Actual:** `entityAtCell` returns `null` for the player's own token, so the branch is dead and the click is treated as a destination move.

## Proposed fix
Have `entityAtCell` include `state.youEntity` for players:

```js
function entityAtCell(x, y) {
  const g = state.grid;
  if (!g) return null;
  const all = state.role === "gm"
    ? state.entities
    : (state.youEntity ? [...state.entities, state.youEntity] : state.entities);
  return all.find((e) => e && e.x === x && e.y === y) || null;
}
```

(Using the existing `allEntities()` helper from BUG-001's fix here as well would be the cleanest single source of truth.)
