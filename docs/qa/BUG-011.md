# BUG-011 — Join rejection (e.g. "session full") shows no feedback to the user

**Severity:** P3 (minor/cosmetic — server still enforces the 1-GM/6-player cap; the 7th joiner just silently fails)
**Component:** Frontend — `app/static/app.js` (error routing) / `app/static/index.html`

## File:line
- `app/static/app.js:238` — `onError(msg)` → `toast(m, "error")`
- `app/static/app.js:256` — `toast()` appends into `els.toasts` = `#toasts`
- `app/static/index.html:140` — `#toasts` is a child of `#map-view`
- `app/static/app.js:28` — `lobbyStatus: $("#lobby-status")` (declared, **never written**)
- `app/static/index.html:27` — `#lobby-status` (in the lobby, never populated)

## Why it's wrong
A **join** rejection is delivered as `{type:"error"}` from the server (`session full` for a 7th non-GM or a 2nd GM; `name required`; `role must be 'gm' or 'player'`). The client routes every error through `toast()`, which appends to `#toasts` — but `#toasts` lives inside `#map-view`, which is **hidden** while the user is still on the lobby (`state.joined` is false until a `welcome` arrives). So the rejected joiner sees **nothing**: the button stays enabled, no message appears.

The lobby *does* have a dedicated status slot — `#lobby-status` (role="status"), wired into `els.lobbyStatus` — but it is never populated anywhere in the code. The intended surface for join errors is unused.

## Repro steps
1. Start the server. Fill a session with 1 GM + 6 players (7 sockets, session id `default`).
2. 8th tab: enter a name, click **Join as Player**.
3. Server replies `{"type":"error","message":"session full"}`.
4. Expected: an error is shown. Actual: the lobby is still shown, `#toasts` (hidden, inside the still-`hidden` `#map-view`) receives the toast, and the user sees no feedback at all.

## Expected vs actual
- **Expected:** a join rejection is surfaced in the lobby (e.g. in `#lobby-status`), telling the user the session is full.
- **Actual:** the rejection toast is appended to a hidden container; the user gets no feedback.

## Proposed fix
In `onError` (or `join()`), when `state.joined` is false, route the message to the lobby: `els.lobbyStatus.textContent = m;` (and/or show a toast only after a `welcome` has been seen). E.g.:

```js
function onError(msg) {
  const m = msg.message || "error";
  if (!state.joined) { els.lobbyStatus.textContent = m; return; }
  // ... existing toast / "Move anyway" handling
}
```
