# BUG-004 — PNG Average/Paeth filter reconstruction corrupted for multi-channel images

**Severity:** P1 (major — silently corrupts wall detection for real RGB/RGBA PNGs)
**Component:** Backend — `app/imaging.py` (PNG decode)

## File:line
- `app/imaging.py:190` — Average filter: `up = prev_row[x] if prev_row is not None else 0`
- `app/imaging.py:197` — Paeth filter: `up = prev_row[x] if prev_row is not None else 0`
- `app/imaging.py:198-200` — Paeth filter: `upleft = prev_row[x - channels] ...`

## Why it's wrong
The per-scanline reconstruction loop iterates **per pixel** (`for x in range(0, stride, channels)`) and, within each pixel, per channel (`for c in range(channels)`). But the "up" and "up-left" references are computed **once per pixel** using the byte index `x`, not `x + c` for each channel:

- **Average** (PNG spec: `recon = raw + (left + up) // 2`, where `up` is the byte directly above at the *same byte offset*): `up = prev_row[x]` is only correct for channel `c == 0`. For the green/blue channels (`c = 1,2`) it uses `prev_row[x]` instead of `prev_row[x + c]`.
- **Paeth** (spec: predictor from left/up/up-left at the same byte offset): `up = prev_row[x]` and `upleft = prev_row[x - channels]` are both wrong for `c > 0` (they should be `prev_row[x + c]` and `prev_row[x + c - channels]`).

Consequence: any **multi-channel** PNG (color type 2 = RGB, 6 = RGBA — the common case for map images) whose scanlines use the **Average or Paeth** filter decodes to wrong pixel values. `to_gray` then runs on corrupted data → Otsu/binarize/majority classify walls in the wrong places. **Grayscale** PNGs (color type 0, `channels == 1`) are unaffected (`x + c == x`), and **Sub/Up/None** filters are implemented correctly — which is why the tests never catch this.

**Why tests are green:** `encode_png` (used by every synthetic fixture) writes filter byte `0` (None) on every scanline, so the Sub/Up/Average/Paeth reconstruction branches are **never exercised** by the suite (searched `tests/` for `ftype` — no matches). Real PNGs from ImageMagick/browsers/etc. very commonly use Paeth (adaptive filtering), so a GM uploading a typical RGB PNG map is likely to hit this.

## Repro steps
1. Take a real RGB PNG map (dark walls on light paper) that uses Paeth/Average filtering (verify: `python -c "import zlib,struct,..."` or just generate with ImageMagick, which defaults to Paeth).
2. `POST /api/maps/upload` with its base64.
3. Compare the detected grid to the obvious layout — walls appear in wrong cells.
4. Control: re-encode the same image with `PNG_FILTER_NONE` (or convert to grayscale) → detection is correct.

## Expected vs actual
- **Expected:** decoded pixels match the source image for all filter types and color types.
- **Actual:** green/blue channels of RGB/RGBA images using Average/Paeth filters are shifted by the wrong "up"/"up-left" samples → corrupted gray → wrong walls/doorways.

## Proposed fix
Move the `up`/`upleft` reads **inside** the channel loop and index by the actual byte `x + c`:

```python
elif ftype == 3:  # Average
    for x in range(0, stride, channels):
        left = cur[x - channels] if x >= channels else 0
        for c in range(channels):
            up = prev_row[x + c] if prev_row is not None else 0
            a = (left + up) >> 1
            cur[x + c] = (raw[p_off + x + c] + a) & 0xFF
            left = cur[x + c]
else:  # 4: Paeth
    for x in range(0, stride, channels):
        left = cur[x - channels] if x >= channels else 0
        for c in range(channels):
            up     = prev_row[x + c] if prev_row is not None else 0
            upleft = prev_row[x + c - channels] if (prev_row is not None and x + c >= channels) else 0
            p = left + up - upleft
            pa, pb, pc = abs(p - left), abs(p - up), abs(p - upleft)
            if pa <= pb and pa <= pc: pr = left
            elif pb <= pc:           pr = up
            else:                    pr = upleft
            cur[x + c] = (raw[p_off + x + c] + pr) & 0xFF
            left = cur[x + c]
```
