# BUG-006 — GM's own character is missing from the awareness list (GM view)

**Severity:** P2 (moderate — GM cannot see/select their own token via the sidebar)
**Component:** Frontend — `app/static/app.js` `drawSidebar()`

## File:line
- `app/static/app.js:632` — `if (isOwn) continue;` inside the awareness loop (the "already rendered above" skip)
- `app/static/app.js:621` — the "own character first row" block is guarded by `state.role === "player"` only
- `app/awareness.py` — `build_awareness` for a GM includes the GM's own `gm_character` item

## Why it's wrong
For a **GM**, `state.awareness` contains an item for *every* entity **including the GM's own** `gm_character` (the server does not exclude the GM's own entity — only players get their own entity excluded). In `drawSidebar`, the loop computes `isOwn = (item.entity_id === state.you.entity_id)` and `continue`s, assuming that entity "was already rendered above". But the own-row block at line 621 only runs when `state.role === "player"`. For a GM, neither path renders the GM's own entity:

- The own-row block is skipped (`state.role !== "player"`).
- The loop `continue`s past the GM's own entity.

Result: the GM's own `gm_character` never appears as a row in the awareness list. The GM's token still renders on the canvas (full token + awareness marker) and can be selected by clicking it, but it is absent from the sidebar list — and the `#awareness-summary` counts it (it's counted before the `continue`) while the list omits it, so the summary and the list disagree by one.

## Repro steps
1. (Requires BUG-001 fixed.) Join as GM on a session with the sample map.
2. Open the sidebar → Awareness.
3. The GM's own character (the `gm_character` spawned at join) is **not** listed as a row, even though it is visible on the map and the summary count includes it.

## Expected vs actual
- **Expected (wireframes §5.2 GM view):** every entity — including the GM's own — appears as a selectable row with name + kind·team + coords.
- **Actual:** the GM's own entity is absent from the list; summary count and list length differ by 1.

## Proposed fix
In the awareness loop, only `continue` for a *player*'s own entity (which was rendered in the own-row block). For a GM, fall through and render the row normally:

```js
const isOwn = state.you && state.you.entity_id ? item.entity_id === state.you.entity_id : false;
if (isOwn && state.role === "player") continue; // players: rendered above
// GM: render the row (own gm_character) as any other
```
