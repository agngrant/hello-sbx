# BUG-009 — Upload file picker accepts JPG/WEBP that the server can only decode as PNG/BMP

**Severity:** P3 (minor — misleading UX; the failure path itself works)
**Component:** Frontend `app/static/index.html` ↔ backend `app/main.py` / `app/imaging.py`

## File:line
- `app/static/index.html:50` — `<input id="upload-file" ... accept=".png,.bmp,.jpg,.jpeg,.webp" />`
- `app/static/index.html:49` (label) — `Image (png / bmp)` (label says png/bmp)
- `app/imaging.py:47` — `decode_image` only handles `PNG_SIGNATURE` / `BMP_SIGNATURE`
- `app/main.py:349` — upload 400 path: `self._send_error_json(400, str(exc))` → "not a supported image…"

## Repro steps
1. Open the upload form; pick a `.jpg` (the picker allows it).
2. Click **Upload & detect**.

## Expected vs actual
- **Expected (wireframes §7.1 "accept: png/jpg"):** either JPEG works, or the picker only offers supported formats.
- **Actual:** the request is sent, the server 400s with `not a supported image: expected PNG or BMP signature`, and the client shows `Upload failed: not a supported image: …`. The `accept` list (`.jpg,.jpeg,.webp`) advertises formats that can never succeed, and the label ("png / bmp") contradicts the picker.

## Proposed fix
Either restrict `accept=".png,.bmp"` (recommended — matches the stdlib-only decoder and the body copy "PNG or BMP"), or add JPEG/WebP decoding (not feasible stdlib-only). One-line fix: change the `accept` attribute to `.png,.bmp`.
