# BUG-001 — Undefined `allEntities()` crashes the map render for every client

**Severity:** P0 (blocks core use)
**Component:** Frontend — `app/static/app.js`

## File:line
- `app/static/app.js:458` — `const entities = allEntities();` (inside `drawEntitiesAndDots`)
- `app/static/app.js:962` — `const e = allEntities().find(...)` (inside the global `keydown` handler)

`allEntities` is called in both places but is **defined nowhere** in the file (searched the whole repo: only those two call sites exist).

## Repro steps
1. Start the server (`.venv/bin/python -m app.main`), open `http://127.0.0.1:8000` in any browser.
2. Enter a name, click **Join as GM** (or Player).
3. Server sends `welcome`. Client runs `onWelcome → applyState → layoutCanvas → drawGridOnCanvas → drawEntitiesAndDots`.

## Expected vs actual
- **Expected:** the map grid + tokens + awareness dots render.
- **Actual:** `drawEntitiesAndDots` throws `ReferenceError: allEntities is not defined` on the first render. Because the throw happens inside `applyState` (line 198 calls `layoutCanvas()`), the rest of the welcome path (`showView`, `updateControlHint`) is skipped. The map canvas is never drawn and no entities/dots are shown. The same `ReferenceError` also fires on the second call site the first time a key is pressed while an entity is selected (line 962).

**Impact:** the entire map view is broken for **every** client (GM and players) on join. This is the single highest-impact defect; it masks most other frontend behavior.

## Proposed fix
Define a helper that returns the full renderable entity list (GM: all; player: others + own):

```js
function allEntities() {
  if (state.role === "gm") return state.entities;
  const own = state.you ? state.youEntity : null;
  return own ? [...state.entities, own] : [...state.entities];
}
```

Then `drawEntitiesAndDots` (line 458) and the keyboard handler (line 962) work as written. (Note: `state.youEntity` is a live reference updated by `applyState`, so it always carries the current position.)

## Note
Until this is fixed, no browser-side behavior past the first render can be exercised. Re-run this repro after the fix before trusting any other frontend verdict.
